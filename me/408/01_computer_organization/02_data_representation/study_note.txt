2. 为什么负数原码第一位是 1？
原码用 最高位当符号位：

符号位	含义
0正
1负

反码（负数）
规则：符号位保持 1，其余位按位取反（0↔1）

原码 -5:  1 000 0101
反码:     1 111 1010
          ↑符号不动  ↑后面全部取反

补码（负数）——408 最重要
两种等价算法，会一种即可：

方法 A（最常用）：
先写绝对值的原码 → 全体按位取反再 +1（得到补码）
+5:     0000 0101
取反:   1111 1010
再+1:   1111 1011   ← 这就是 -5 的补码

方法 B：
先求反码，再 +1
反码: 1111 1010
+1:   1111 1011   ← 补码

总结 求负数补码
1：正数的原码 按位取反再+1
2：自己反码再+1

为什么计算机更爱用补码，而不是原码做加减？（一句话就行）

用补码可以把减法和加法统一成一套加法电路，硬件更简单；而且 0 只有一种表示。

解释：
1.「减法和加法统一成一套电路」是什么意思？
人算：7 - 3，脑子里是「减法」。

机器更想只做一种事：加法。

补码的规矩正好是：

A - B  =  A + (-B)
而 (-B) 在补码里，就是对 B 取反加一 得到的那个码。
所以硬件只要有：

一个 加法器
一个「取反加一」的小动作（做减法时对第二个数用）
就不用再单独造一套复杂的「减法器逻辑」去处理原码那种符号、借位乱七八糟的情况。

一句话： 减法也变成「加上一个负数的补码」，电路主要围着加法转。

补码让「减一个数」变成「加它的相反数」，机器主要会加法就行；而且零不会有两种写法。


3.「0 只有一种表示」是什么意思？
原码里：

+0 = 0000 0000
-0 = 1000 0000
两个都叫「零」，比较、判断麻烦。

补码里：

只有 0000 0000 表示 0

补码里：
+0 → 0000 0000
对 0 再求一次“相反数”（取反加一）：
0000 0000 → 取反 1111 1111 → +1 → 进位出去后还是 0000 0000
所以 -0 也是 0000 0000，和 +0 同一个码
也就是说：补码里 没有两种零，+0、-0 都是全 0。

4. 8 位补码运算：(+100) + (+50) 的结果（ ）
A. 正确，真值为 150
B. 溢出
C. 结果补码为 1001 0110，真值按有符号解释为负但不算溢出
D. 需要借位，结果为 -106

解析：
题意：在 8 位有符号补码里做 (+100)+(+50)，人算是 150，
但 8 位补码范围只有 -128~127，要判断会不会溢出。

步骤：
  +100:  0110 0100
  +50:   0011 0010
  ---------------
  相加:  1001 0110

说明：
- 结果机器数最高位是 1 → 按有符号看像“负数”
- 但本来两个正数相加 → 典型溢出
- 也可用范围：150 > 127 → 一定溢出

选项：
A ✗ 8位装不下150，不能说结果正确是150
B ✓ 溢出
C ✗ 比特串确实是1001 0110，但就是溢出，不能说“不算溢出”
D ✗ 这是加法不是借位；-106只是溢出后被误读的假真值

答案：B

一句话：两正相加，和超过 2^(n-1)-1，或结果符号位变成1 → 溢出。


借位一般是指减法过程中 发生的借位  比如 

例（十进制）：32 - 5
个位 2 不够减 5，向十位借 1（借来当 10），变成 12 - 5 = 7。

二进制也一样：某一位是 0，要减 1，就向左边更高位借。



























5. 关于溢出判断，正确的是（ ）
A. 最高位有进位就一定溢出
B. 两正数相加得负数，一定溢出
C. 无符号加法的进位就是有符号溢出 OF
D. 溢出后机器数一定变成全 0

解析：
A ✗ 最高位进位 ≠ 一定溢出。
   进位更多用于无符号数；有符号溢出看的是 OF。
   例：(-1)+(-1) → 11111111+11111111，最高位有进位，
   结果 11111110 = -2，有进位但没溢出。

B ✓ 符号判断法：两正相加得负，或两负相加得正 → 一定溢出。
   （第4题 (+100)+(+50) 得到符号位为1，就是这种情况。）

C ✗ 无符号的“进位/借位”和有符号的溢出标志 OF 不是一回事。
   题目若问溢出（有符号），不要直接拿最高位进位当 OF。

D ✗ 溢出后只是结果超出表示范围，机器里仍留下一串错误比特，
   不一定是全0。（第4题溢出后是 10010110，不是0。）

答案：B
